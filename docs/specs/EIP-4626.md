# EIP-4626 — Tokenized Vault Standard

**Status:** Final (ratified, broadly adopted)
**Source:** https://eips.ethereum.org/EIPS/eip-4626
**Last researched:** 2026-05-02

## Verdict for zhgg: **POST-HACKATHON (not testnet-viable)**

The "agent's idle USDC earns yield" narrative is real on mainnet, but every concrete
piece fails the hackathon constraint set: no canonical-USDC 4626 vault exists on Base
Sepolia, parking funds breaks zhgg's "key leak = bounded loss" invariant, and judges
won't differentiate this from generic DeFi composability. Park as a post-hackathon
roadmap item: "AgentReceiverWallet v2 with optional `IERC4626 yieldVault`" once mainnet
capital is real.

## What it does

Canonical "tokenized vault" interface:
- `deposit(assets, receiver) → shares`
- `withdraw(assets, receiver, owner) → shares`
- `redeem(shares, receiver, owner) → assets`
- `convertToShares` / `convertToAssets` price views

Mature, broadly adopted (Yearn V3, Morpho Blue, Aave's `StaticATokenLM` wrapper, Lido
sub-wrappers). **Aave aTokens themselves are rebasing and NOT 4626-conformant** — the
wrapper [`bgd-labs/static-a-token-v3`](https://github.com/bgd-labs/static-a-token-v3)
(a.k.a. `StaticATokenLM`) repackages an aToken into a non-rebasing 4626 share that
exposes both supply yield and any liquidity-mining rewards.

## Hypothetical integration (NOT recommended now)

The cleanest hook would be `AgentReceiverWallet.sol:81` — `splitMyBalance(IERC20 asset)`.
Current flow: `balanceOf → forceApprove → splitERC20`. A 4626-aware variant would:
1. At deploy, store optional `IERC4626 yieldVault` immutable
2. In `splitMyBalance`, before `bal` check at line 82, call
   `yieldVault.redeem(yieldVault.balanceOf(address(this)), address(this), address(this))`
   to atomic-withdraw to raw USDC, then proceed unchanged from line 82 onward
3. Add permissionless `parkIdle()` function that takes current raw balance and
   `deposit`s it into `yieldVault` whenever it exceeds a high-water mark

Atomic withdraw → pay path: ~80-120k extra gas on Base, `nonReentrant` covers reentrancy.

## Why this breaks zhgg's security story

- **Bounded-loss invariant compromised**: today, a Turnkey key leak only costs whatever
  USDC sits in the receiver between `splitMyBalance` calls. Park funds in Aave and an
  Aave guardian pause / oracle manipulation / Morpho-style market freeze can lock funds
  beyond what the agent's own keys control.
- **New attack surfaces**:
  - 4626 first-deposit share manipulation (donation / inflation attacks)
  - Withdrawal queues (Yearn V3 has them — `splitMyBalance` could revert)
  - Oracle dependence (Aave stops withdrawals if oracle is stale)
  - Governance upgrade risk (`StaticATokenLM` is upgradable by Aave Level 1 executor)
- **New liveness dependency**: if `yieldVault.redeem` reverts, `splitMyBalance` reverts
  too, breaking the current invariant that splits are always-callable.

## Why judges won't care

ETHGlobal OpenAgents judges care about the *agent loop* (intents, x402 settlement,
ERC-7715 caps, ERC-8004 receipts). "Idle USDC earns yield" is a generic DeFi
composability story that any wallet can claim — it does not differentiate an *agent*
product. On testnet with mock USDC it's literally a no-op visually. **Scope creep
dressed as a feature.**

## Post-hackathon design note

When zhgg launches on mainnet with real capital:
1. Pin the `yieldVault` immutable to a specific audited 4626 (Yearn V3 Base USDC, or
   `StaticATokenLM` over Aave V3 Base canonical USDC)
2. Add a `MIN_YIELD_BALANCE` threshold — only `parkIdle()` when balance > N USDC, so
   tiny payments don't churn vault gas
3. Document the new liveness dependency loudly: "splits depend on vault liveness"
4. Add a `withdrawAllIdle()` escape hatch the iNFT owner can call to migrate away from a
   compromised vault
