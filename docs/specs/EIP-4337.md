## What the paymaster pattern does

ERC-4337 splits the gas-payer from the tx-author via a `Paymaster` contract that the
EntryPoint consults during `handleOps`. Two key functions:

```solidity
function validatePaymasterUserOp(userOp, userOpHash, maxCost)
    external returns (bytes context, uint256 validationData);

function postOp(PostOpMode mode, bytes context, uint256 actualGasCost)
    external;
```

The paymaster pays the actual ETH to the EntryPoint, then debits an ERC-20 from the
smart account inside `postOp`. Result: agent only holds USDC, never ETH.

## Real cost — `splitERC20` ~80k gas on Base Sepolia

At Base Sepolia ~0.05 gwei `maxFeePerGas`:
- Direct ETH: 80k gas × 0.05 gwei = ~$0.012 USD
- Through Pimlico ERC-20: ~$0.013 USDC (10% markup)
- Through Coinbase CDP: ~$0.013 invoiced (7% markup) — if FeeSplitter allowlisted
- ERC-4337 adds **~25-40k gas** of EntryPoint/paymaster overhead → realistic billed:
  **~$0.018-0.020 USDC per split**
- Latency: **~1-3s p50** for Pimlico's public bundler vs **~200ms** for direct EOA
  broadcast

## Why NOT real impl by May 6

`AgentReceiverWallet.sol` is **NOT ERC-4337 compatible**:
- No `validateUserOp(...)` function
- No nonce manager
- No EntryPoint association
- Key write path (`splitMyBalance`) is permissionless — anyone can call it, gas
  abstraction moot for that function

Adding gas abstraction means **either**:
1. **Re-author signer wallet as 4337 SimpleAccount** (~200-400 LOC Solidity + deploy
   script). Existing `AgentReceiverWallet` stays as receive/split contract — it'd be
   the SimpleAccount's *target* (`executeBatch` use case).
2. **EIP-7702 delegate the iNFT-owner EOA** to a `SimpleAccount` implementation. No new
   deploy — one tx upgrades the EOA in place. Coinbase's CDP doc explicitly mentions
   this path.

Option 2 is smaller; option 1 is what Pimlico's tutorial walks through. Either way,
**400-600 LOC** once tests + deploy script + iNFT-owner key wiring are honest.
