## What it is (3 sentences)

0G is a modular AI-native L1 stack composed of a chain (EVM-compatible), a programmable data-availability layer (0G DA), a content-addressed storage layer with both Log and KV semantics (0G Storage), and a decentralized GPU marketplace for verifiable inference inside TEEs (0G Compute). For zhgg we use 0G Galileo as the settlement chain for ERC-7857 iNFT-backed agents, 0G Storage for encrypted agent memory addressed by Merkle root, and 0G Compute for TEE-attested inference whose signed responses can be verified on-chain. The stack lets us mint an agent NFT, anchor its mutable memory in a single 32-byte root, and prove that any inference came from the model the iNFT advertises.

## The 0G Stack

### 0G Chain (EVM L1)

- EVM-equivalent execution; standard `ethers` / `viem` clients work.
- Galileo testnet: chain `16602`, RPC `https://evmrpc-testnet.0g.ai`.
- Native gas token: `0G`. Faucet caps at 0.1 0G/wallet/day, so design tests to be gas-frugal.

### 0G Storage

A decentralized storage layer with two access modes:

- **Log layer**: append-only, content-addressed by Merkle root. Used for blobs (model weights, encrypted memory snapshots, datasets).
- **KV layer**: stream-scoped key/value writes batched into the Flow contract. Used for mutable, queryable state.

Endpoints (Galileo):

- EVM RPC: `https://evmrpc-testnet.0g.ai`
- Storage Indexer (Turbo): `https://indexer-storage-testnet-turbo.0g.ai`
- Storage explorer: `https://storagescan-galileo.0g.ai`

The indexer auto-discovers the Flow contract; you do not pass the Flow address yourself for log uploads.

### 0G Compute (verifiable inference)

A decentralized GPU marketplace with two integration paths:

- **Compute Router** (recommended for hackathons): OpenAI-compatible endpoint. Production: `https://router-api.0g.ai/v1`. Testnet: **`https://router-api-testnet.integratenetwork.work/v1`** (verified 2026-05-03; the production URL rejects testnet `sk-` keys with 401). Auth via `sk-` keys minted at `pc.testnet.0g.ai`. Ledger creation requires depositing **>= 3 OG** before keys can authorize calls.
- **Direct broker SDK** (`@0glabs/0g-serving-broker`): per-provider account management, on-chain ledger, TEE attestation verification. Use this when you need cryptographic proof that a specific provider executed the inference.

Every provider runs the model inside a TEE (Trusted Execution Environment, e.g. Intel TDX). Responses are signed by the TEE's key; the broker SDK verifies that signature so you can prove the response is genuine.

Cost reference from the docs: roughly $0.003 per 1K tokens (vs ~$0.03 for GPT-4).

### 0G DA

Data availability layer. Galileo entrypoint: `DAEntrance` at `0xE75A073dA5bb7b0eC622170Fd268f35E675a957B`. Not used directly in the zhgg P0 path — listed for completeness.

## ERC-7857 (iNFT)

**Spec page**: `https://docs.0g.ai/developer-hub/building-on-0g/inft/erc7857`
**Overview**: `https://docs.0g.ai/developer-hub/building-on-0g/inft/inft-overview`
**Reference repo**: `https://github.com/0gfoundation/0g-agent-nft/tree/eip-7857-draft`

ERC-7857 extends ERC-721 with primitives for transferring **encrypted** intelligence (model weights, memory, prompts) alongside ownership. The 7857 addition over 7212 / 721: a *sealedKey* + *proof* tuple that re-encrypts the ciphertext for the new owner via a TEE oracle on every transfer.

### Core interface (verbatim from docs)

```solidity
interface IERC7857 is IERC721 {
    function transfer(
        address from,
        address to,
        uint256 tokenId,
        bytes calldata sealedKey,
        bytes calldata proof
    ) external;

    function clone(
        address to,
        uint256 tokenId,
        bytes calldata sealedKey,
        bytes calldata proof
    ) external returns (uint256 newTokenId);

    function authorizeUsage(
        uint256 tokenId,
        address executor,
        bytes calldata permissions
    ) external;
}
```

### Reference implementation storage

The reference contract uses three internal mappings:

```solidity
mapping(uint256 => bytes32) private _metadataHashes;        // memory root / commitment
mapping(uint256 => string)  private _encryptedURIs;         // 0G Storage pointer
mapping(uint256 => mapping(address => bytes)) private _authorizations;
```

### Events

```solidity
event MetadataUpdated(uint256 indexed tokenId, bytes32 newHash);
event UsageAuthorized(uint256 indexed tokenId, address indexed executor);
event OracleUpdated(address oldOracle, address newOracle);
```

A constant `PROOF_VALIDITY_PERIOD = 1 hours` bounds how long a re-encryption proof remains valid.

### How memory updates work

1. Encrypt the new memory blob client-side with a fresh symmetric key.
2. Upload the ciphertext to 0G Storage. You get a **root hash** (`bytes32`).
3. Call the contract's update path — the reference impl emits `MetadataUpdated(tokenId, newHash)` and rotates the `_encryptedURIs[tokenId]` to the new 0G Storage URI.
4. Anyone reading the iNFT now sees the new commitment; they need the sealed key (delivered out-of-band per spec) to actually decrypt.

### Authorization (delegated execution)

`authorizeUsage(tokenId, executor, permissions)` lets the owner grant an `executor` (e.g. an automated trader, a 0G Compute provider) bounded permission to run inference against the iNFT's model. `permissions` is opaque ABI-encoded bytes — typically a struct describing scope, expiry, max calls.

### Transfer flow (six-step, from docs)

1. Encryption & commitment — metadata encrypted with hash commitment.
2. Secure transfer initiation — oracle decrypts in a TEE.
3. Re-encryption for receiver — fresh key generated and metadata re-encrypted.
4. Key delivery — new key encrypted with receiver's public key.
5. Verification & finalization — smart contract verifies proofs.
6. Access granted — receiver decrypts key and accesses intelligence.

### Galileo deployment address

**Unknown / not published.** The docs reference the standard but do not list a canonical deployed `IERC7857` on Galileo. Treat 7857 as an interface to deploy yourself from the reference repo (`0g-agent-nft` on the `eip-7857-draft` branch). For zhgg we will deploy our own and pin the address in `contracts/deployments/galileo.json`.

## 0G Compute SDK (`@0glabs/0g-serving-broker`)

### Install

```bash
pnpm add @0glabs/0g-serving-broker
# global CLI:
pnpm add @0glabs/0g-serving-broker -g
```

### Ethers version

The broker docs use **ethers v6** (`import { ethers } from "ethers"`, `JsonRpcProvider`, `BrowserProvider`, `parseEther`/`formatEther`). The legacy "broker requires ethers v5" guidance from earlier 0G releases is **superseded**. Verify the installed `@0glabs/0g-serving-broker` peer-dep range at install time — but the documented examples are v6.

### Auth flow (Node)

```typescript
import { ethers } from "ethers";
import { createZGComputeNetworkBroker } from "@0glabs/0g-serving-broker";

const RPC_URL = process.env.NODE_ENV === 'production'
  ? "https://evmrpc.0g.ai"
  : "https://evmrpc-testnet.0g.ai";

const provider = new ethers.JsonRpcProvider(RPC_URL);
const wallet = new ethers.Wallet(process.env.PRIVATE_KEY!, provider);
const broker = await createZGComputeNetworkBroker(wallet);
```

### Auth flow (Browser)

```typescript
import { BrowserProvider } from "ethers";
import { createZGComputeNetworkBroker } from "@0glabs/0g-serving-broker";

if (typeof window.ethereum === "undefined") {
  throw new Error("Please install MetaMask");
}

const provider = new BrowserProvider(window.ethereum);
const signer = await provider.getSigner();
const broker = await createZGComputeNetworkBroker(signer);
```

### Ledger funding

```typescript
// Deposit 10 0G into the main ledger account.
await broker.ledger.depositFund(10);

// Transfer to a provider sub-account (auto-acknowledges the provider's TEE signer).
await broker.ledger.transferFund(
  providerAddress,
  'inference',
  BigInt(1) * BigInt(10 ** 18)
);

// Inspect balance.
const account = await broker.ledger.getLedger();
console.log(`Total: ${ethers.formatEther(account.totalBalance)} 0G`);
console.log(`Available: ${ethers.formatEther(account.availableBalance)} 0G`);

// Refunds.
await broker.ledger.retrieveFund("inference"); // reclaim from sub-account
await broker.ledger.refund(5);                  // withdraw 5 0G to wallet
```

Minimum balance constraints (from docs):
- Ledger creation requires **>= 3 0G**.
- Each provider sub-account locks **1 0G**.
- Refunds have a **24-hour lock period**.

### Provider discovery

```typescript
const services = await broker.inference.listService();

const chatbotServices  = services.filter(s => s.serviceType === 'chatbot');
const imageServices    = services.filter(s => s.serviceType === 'text-to-image');
const speechServices   = services.filter(s => s.serviceType === 'speech-to-text');
```

### Inference call (chat) with TEE verification

```typescript
const messages = [{ role: "user", content: "Hello!" }];

const { endpoint, model } = await broker.inference.getServiceMetadata(providerAddress);
const headers = await broker.inference.getRequestHeaders(providerAddress);

const response = await fetch(`${endpoint}/chat/completions`, {
  method: "POST",
  headers: { "Content-Type": "application/json", ...headers },
  body: JSON.stringify({ messages, model }),
});

const data = await response.json();
const answer = data.choices[0].message.content;

// Verify the response was signed inside the provider's TEE.
const chatID = response.headers.get("ZG-Res-Key") || data.id;
if (chatID) {
  const isValid = await broker.inference.processResponse(providerAddress, chatID);
}
```

### TEE attestation

`broker.inference.processResponse(providerAddress, chatID)` returns `Promise<boolean>`. It pulls the TEE-signed receipt indexed by `chatID` (from the `ZG-Res-Key` response header) and verifies the signature against the provider's on-chain TEE pubkey. **Calling `processResponse` is optional but is the only thing that turns "OpenAI-shaped JSON" into "verifiable inference." For zhgg, always call it on the server boundary.**

### Cost model

- Pay-per-call, denominated in 0G.
- Provider charges are deducted from the **provider sub-account**, not the main ledger.
- Pricing is provider-defined and exposed in `getServiceMetadata`.
- Reference floor: ~$0.003 per 1K tokens (docs).
- Refund flow: `retrieveFund` -> 24h lock -> `refund` to wallet.

### Compute Router alternative (when you don't need direct attestation)

```bash
curl https://router-api.0g.ai/v1/chat/completions \
  -H "Content-Type: application/json" \
```

## 0G Storage SDK (`@0glabs/0g-ts-sdk`)

> Note: the docs show the package under the `@0gfoundation/0g-ts-sdk` namespace. The `@0glabs` namespace also publishes the SDK and is the canonical org alias. Verify the published name on npm before pinning. The user prompt asks us to refer to it as `@0glabs/0g-ts-sdk` — match against npm at install time.

### Install

```bash
npm install @0gfoundation/0g-ts-sdk ethers
# or:
bun add @0gfoundation/0g-ts-sdk ethers
```

`ethers` is a peer dependency. The storage SDK examples use **ethers v6** (`JsonRpcProvider`).

### Indexer setup

```typescript
import { ethers } from "ethers";
import { Indexer, ZgFile, Batcher } from "@0gfoundation/0g-ts-sdk";

const evmRpc    = "https://evmrpc-testnet.0g.ai";
const indRpc    = "https://indexer-storage-testnet-turbo.0g.ai";
const privateKey = process.env.PRIVATE_KEY!; // must hold gas

const provider = new ethers.JsonRpcProvider(evmRpc);
const signer   = new ethers.Wallet(privateKey, provider);
const indexer  = new Indexer(indRpc);
```

The indexer auto-discovers the Flow contract; you do not pass it explicitly for log uploads.

### Log upload (file blob)

```typescript
async function uploadFile(filePath: string) {
  const file = await ZgFile.fromFilePath(filePath);

  const [tree, treeErr] = await file.merkleTree();
  if (treeErr !== null) throw new Error(`Merkle tree error: ${treeErr}`);

  console.log("File Root Hash:", tree!.rootHash());

  const [tx, uploadErr] = await indexer.upload(file, evmRpc, signer);
  if (uploadErr !== null) throw new Error(`Upload error: ${uploadErr}`);

  await file.close();
  return { tx, rootHash: tree!.rootHash() };
}
```

### Root hash calculation (without uploading)

```typescript
const file = await ZgFile.fromFilePath(filePath);
const [tree, err] = await file.merkleTree();
if (err === null) {
  console.log("File Root Hash:", tree!.rootHash());
}
```

The root hash is the **only** thing you need to retrieve the file later. Pin it on-chain (e.g. in `_metadataHashes[tokenId]` of your iNFT).

### KV upload (stream-scoped key/value)

```typescript
async function uploadToKV(streamId: string, key: string, value: string) {
  const [nodes, err] = await indexer.selectNodes(1);
  if (err !== null) throw err;

  const batcher    = new Batcher(1, nodes!, flowContract, evmRpc);
  const keyBytes   = Uint8Array.from(Buffer.from(key, "utf-8"));
  const valueBytes = Uint8Array.from(Buffer.from(value, "utf-8"));

  batcher.streamDataBuilder.set(streamId, keyBytes, valueBytes);

  const [tx, batchErr] = await batcher.exec();
  if (batchErr !== null) throw batchErr;

  return tx;
}
```

The KV path needs an explicit `flowContract` instance (Flow address on Galileo: `0x22E03a6A89B950F1c82ec5e74F8eCa321a105296`).

### Read pattern

```typescript
const err = await indexer.download(rootHash, outputPath, /* withProof */ true);
if (err !== null) throw err;
```

The third argument is a Merkle-proof toggle; for production-grade memory loads, leave it `true` so the SDK validates the bytes against `rootHash`.

## Gotchas

### ethers v5 vs v6

Older 0G blog posts and pre-Galileo broker readmes referenced **ethers v5**. The current `@0glabs/0g-serving-broker` and `@0gfoundation/0g-ts-sdk` documented examples both use **ethers v6** (`JsonRpcProvider`, `Wallet`, `parseEther`, `BrowserProvider`). **Pin v6** in zhgg unless an install-time peer-dep error tells you otherwise. If the broker errors at runtime with `provider.getSigner is not a function`-style messages, that's the v5/v6 mismatch — fix by upgrading, not downgrading.

### Indexer endpoint vs RPC endpoint

These are different services on different hostnames:

- **EVM RPC**: `https://evmrpc-testnet.0g.ai` (read/write chain state, send tx).
- **Storage indexer**: `https://indexer-storage-testnet-turbo.0g.ai` (discover storage nodes, route uploads/downloads).

Mixing them up gives confusing errors (`indexer.upload` against the EVM RPC will look like a 405 or HTML response). Keep them as separate environment variables: `ZG_EVM_RPC` and `ZG_INDEXER_RPC`.

### Chain ID confusion: 16601 vs 16602

There was an earlier 0G testnet configuration that surfaced under chain ID `16601`. **Galileo is `16602`.** Symptoms of using the wrong ID: wallets prompt to "switch network" repeatedly, `ethers` throws `network changed` mid-tx, contract calls revert with no decoded error because the ABI is from a different deployment. Hard-pin `chainId: 16602` in your `wagmi.config`, `viem` chain object, and `hardhat.config.ts`.

### TEE attestation format

The broker SDK abstracts attestation into one boolean: `broker.inference.processResponse(providerAddress, chatID) -> boolean`. Under the hood:

- The provider's TEE signs each response with a key registered on-chain.
- The `ZG-Res-Key` HTTP response header carries a chat-scoped identifier.
- The SDK fetches the signature for that ID and verifies it against the provider's on-chain TEE pubkey.

If you want to verify on-chain (e.g. inside a settlement contract), you need the raw signature + the provider's TEE pubkey + the canonical message — not currently exposed as a single helper in the docs. **For P0, run `processResponse` server-side and store the boolean as part of the agent's audit log.**

### iNFT manifest format

The reference contract pins:
- a `bytes32` memory hash (the 0G Storage root),
- a `string` encrypted URI (where to fetch the ciphertext from 0G Storage),
- an authorization map keyed by `(tokenId, executor)`.

There is **no documented JSON manifest schema** beyond that. zhgg defines its own manifest (e.g. `{ memoryRoot, capabilities[], modelHash, version }`) and stores it as the encrypted blob; the on-chain `bytes32` is the Merkle root of that blob. Pin the schema in `packages/sdk/src/schema/manifest.ts` so future versions can migrate cleanly.

### Faucet rate-limit

0.1 0G per wallet per day is enough for ~hundreds of contract reads but *not* enough to upload a multi-MB model. Plan: pre-fund a single deployer wallet from multiple faucet drips, then internal-transfer to ephemeral test wallets.

### Package name drift

The storage SDK appears in the docs as `@0gfoundation/0g-ts-sdk`. The hackathon prompt and some 0G Labs READMEs reference `@0glabs/...`. These are likely the same package under two npm orgs (`0gfoundation` is the publishing org; `0glabs` is the GitHub org). Verify on `npm view @0gfoundation/0g-ts-sdk` and `npm view @0glabs/0g-ts-sdk` before locking your `package.json`.
